# 今晚吃什么？

面向 FoloToy AI Passport（ESP32-C3、240×320、无 PSRAM）的离线抽签小游戏。
开机直达新设计的首页，采用参考图的深色背景、暖白文字、灰色辅助信息与黄色焦点。
不编译食物照片、GIF、联网服务、音频或完整中文字体。

## 开发基线和功能

从官方 main `25add0044cb3e8ce2319c258ae96551f0ffcc2df` 创建
`feature/tonight-dinner` 分支。原 `ai-passport-main` 压缩包目录未修改。
已阅读 AGENTS、AI 开发指南、硬件指南，检查官方 `demo/*` 分支清单、
`demo/rock-paper-scissors` 的三键模式，以及“今天吃什么”和离线图鉴的记录。
当前上游参考资料位于 `docs/reference/`，根目录没有 `reference/` 或 `plays/`。
旧示例在按键回调直接访问界面的方式不沿用；按当前规范仅在回调入队。
BSP 驱动和分区表均未修改。

四个主要页面为首页、两阶段抽取、结果、设置。子菜单、空池提示、重置确认及
轻量应用入口都复用同一屏幕。官方基线是独立固件模板，没有可返回的插件加载器：
首页长按 OK 返回本应用的轻量入口，再按 OK 进入；不切换到另一个原厂固件，
也不进入官方硬件测试菜单。

## 卡通装饰更新（1.1.0）

首页“开始抽”上方加入金色拱门薯条、笑脸汉堡、饮料杯和戴皇冠的小雪人，
呼应参考图里的快餐、冰饮元素。抽取页显示雪人与薯条，结果页加入庆祝小贴纸，
设置标题旁放雪人和饮料杯。较密集的设置子菜单保持清爽。
装饰沿用深蓝、暖白、灰色、黄色四种主色，在屏幕背景绘制事件中用 LVGL
矩形和线条绘制；没有图片资源、画布缓冲、新增控件或定时器。
状态改变会重绘背景，避免旧装饰残留，整屏仍为 23 个控件。
24 KB 池的真实 LVGL 电脑测试通过 4,500 次状态渲染，结束后空闲 3,440 字节、
最大连续空闲 2,816 字节。实屏效果尚未验证。

## 三键操作

| 页面 | UP / DOWN | OK 短按 | OK 长按 |
| --- | --- | --- | --- |
| 首页 | 切换“开始抽 / 设置” | 执行选中项 | 退出到应用入口 |
| 抽取和彩蛋 | 忽略 | 忽略 | 取消并回首页 |
| 结果 | 切换“就它了 / 再抽一次 / 设置” | 执行选中项 | 回首页 |
| 设置 | 循环移动选项 | 进入子菜单 | 返回来源页（首页或结果） |
| 模式、预算 | 移动选项 | 选择并保存 | 返回设置 |
| 忌口 | 移动标签 | 开关排除标签并保存 | 返回设置 |
| 不喜欢：分类 | 移动分类，六行窗口滚动 | 查看该分类 | 返回设置 |
| 不喜欢：食物 | 选择整类开关或五种食物 | 切换排除并保存 | 返回分类 |
| 空候选池 | 恢复默认 / 返回设置 | 执行 | 回首页 |
| 重置确认 | 取消 / 确认，默认取消 | 执行 | 返回设置 |
| 决定了 | 忽略 | 忽略 | 回首页；不操作 1.5 秒后自动返回 |
| 应用入口 | 单一入口 | 再次进入 | 保持入口 |

`[x]` 表示已选择或已排除，`[ ]` 表示未选择或允许。整类排除优先，但保留单个
食物的排除状态。复用 BSP 的 ADC 防抖，再增加 90 ms 应用防抖。
快速双击按一次普通操作处理，不绑定其他功能。
闲置 60 秒后背光降至 8%，任一有效按键恢复 75%。

## 60 种食物和抽取

需求中全部 **12 类、60 个名称、每类 5 种**均写入
`main/dinner_food_database.c` 的一份常量表，模式不复制数据。
预算作为娱乐性的**上限**：不限 / 等级 1 / 等级 1–2 / 等级 1–3。
忌口标签为辣、海鲜、牛羊肉、生食、油炸，按常见做法标注，仅作娱乐筛选，
不保证某道菜的实际配料。

省钱、重口、聚餐模式对相符食物给予 4 倍权重；清淡模式排除辣、重油和油炸。
预算、忌口和不喜欢始终优先。生成固定 60 字节候选池，多于一个候选时排除
上次结果，再按各分类候选权重选分类、在分类内选食物，避免候选数量不等时
人为偏向某一类。随机种子来自 ESP 本地随机数据与运行时间，选择使用拒绝采样，
不为随机数启用无线电。

LVGL Timer 控制两阶段：0–800 ms 滚动分类，800–1150 ms 停住分类，
1150–1950 ms 滚动食物，1950–2200 ms 停住食物，随后结果短暂黄色闪动。
连续重抽 3–5 次偶尔出现调侃，第 8 次固定提示，第 10 次增加两个各 500 ms
的彩蛋文案后继续正常抽取。“就它了”或从首页开始新一轮会重置重抽次数。
空池明确提供恢复默认与返回设置。

## 持久化和内存

应用状态、食物表、候选池固定大小；控件只创建一次，切页时更新或隐藏。
一个常驻 LVGL Timer，不随重抽新增任务或定时器。保持官方 **24 KB LVGL 池**和
**9,600 字节 DMA 缓冲**，2-bpp 字体放 Flash。文字复制长度受固定文案限制。

按键回调只向静态八事件队列投递。应用任务短暂持 LVGL 锁处理输入和界面，
复制待保存设置后在锁外写 NVS。可选电池任务使用 3,072 字节栈，首屏出现后
才初始化电量计，慢 I2C 不阻塞导航。后台访问 LVGL 均加锁。
退出到应用入口仍保留同一屏幕，不存在后台访问已删除页面的问题；未来若增加
真正销毁页面，必须先停止 Timer 和任务。

NVS 命名空间 `dinner`、键 `settings`，使用版本化 16 字节小端格式，不写入
结构体填充。首次无记录时保存默认；格式、版本、范围错误使用默认；初始化、
保存或提交失败不擦除其他 NVS 数据。保存失败会恢复内存默认并显示提示，
再次成功写入才有持久化保证。真实断电读取仍需上板验证。
每完成 100 次抽取串口输出剩余堆、历史最小堆、最大连续空闲块。

## 重现验证

激活 **ESP-IDF 5.5.3** 后执行：

```bash
./tools/validate.sh --static
./tools/validate.sh --firmware
./tools/validate.sh
./tools/test_dinner_ui.sh
```

官方门禁已加入数据库、筛选、导航、模拟 NVS 重启与失败、字体清单一致性，以及
应用和合并镜像均 **严格小于 3,000,000 字节**的检查。
UI 测试使用项目固定的 LVGL 9.5、实际应用 UI 与字体、24 KB 池和 240×20 RGB565
局部刷新缓冲，输出 `build/preview` 下 PPM 预览；逐字检查三个字号的真实字形，
包含已知缺字负例，并执行 4,500 次状态渲染，断言对象数量固定、内存无持续增长。
这是电脑端真实 LVGL 渲染，不模拟 ESP32 和实体屏幕。

门禁在 `build/firmware/` 保存按哈希命名的完整调试包：匹配的应用/合并 BIN、
ELF、MAP、分区表、引导镜像。用
`python3 tools/archive_firmware.py verify <包目录>` 验证。
可刷入文件为 `build/FoloToy-AI-Passport-full.bin`，地址 **0x0**。
合并镜像的填充区可能覆盖 NVS；兼容分区下需保留设置时使用包内 `flash_args`
分段刷写。不能把仅应用 BIN 写到 0x0。卡通版随后经用户明确授权完成刷写，数据校验与串口启动检查通过，未整片擦除。
实际体积和构建身份见[验证报告](dinner-validation.zh_CN.md)。

## 刷入后的实机验收（刷写与串口启动已完成，实体观察待确认）

1. 明确同意刷机后，选定 ESP32-C3 串口和本次验证的精确固件，确认是否接受
   合并镜像覆盖 NVS；要保留设置则用兼容的分段方式。无需先备份原固件，
   不进行整片擦除。
2. 上电，检查首页是否在 1–2 秒内出现，中文无缺字、边角无遮挡、电量显示
   合理百分比或 `--%`，没有联网界面。
3. 在所有页面验证 UP/DOWN、OK 短按/长按、子菜单逐级返回、首页退出与重进，
   抽取两阶段长按取消，以及快速反复按键。
4. 抽取并“就它了”，检查分类、食物、2.2 秒节奏；连续重抽至少 100 次，
   查看 3–5 / 8 / 10 次彩蛋、多候选不立即重复、串口内存数值稳定。
5. 修改所有模式、预算、忌口；排除分类和单项后断电重启，检查保存。
   排除全部分类触发空池，检查恢复默认、返回设置和重置取消；再测试只剩一种食物。
6. 实屏检查长食物名（尤其火锅类）、错误状态和三种字号；静置 60 秒后各键
   唤醒背光；检查保存与电量读取期间无卡顿，串口无异常、断言或重启。

编译成功、电脑预览、刷写成功均不能代替实机验收。实体屏幕、ADC 时序、
首屏速度、NVS 真断电、电量计和至少 100 次真机抽取稳定性均待验证。
